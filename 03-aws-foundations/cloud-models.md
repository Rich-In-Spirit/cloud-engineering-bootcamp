# Cloud Models

## IaaS
Infrastructure as a Service means renting infrastructure like virtual machines, networking, and storage instead of buying physical hardware.

Example:
- AWS EC2
- Azure Virtual Machines

Why it matters:
Cloud engineers need to understand IaaS because this is where servers, networks, firewalls, and storage are built.

## PaaS
Platform as a Service means the cloud provider manages more of the platform, and the customer focuses more on the application.

Example:
- AWS Elastic Beanstalk
- Azure App Service

Why it matters:
PaaS reduces server management but gives less low-level control.

## SaaS
Software as a Service means using a complete application managed by someone else.

Example:
- Microsoft 365
- Salesforce
- ServiceNow

Why it matters:
Help desk teams often support SaaS. Cloud engineers need to understand how SaaS fits into identity, security, access, and business workflows.

## Public Cloud
Cloud resources owned and operated by a cloud provider and used over the internet.

Example:
- AWS
- Azure
- Google Cloud

## Private Cloud
Cloud-like infrastructure dedicated to one organization.

Example:
- VMware private cloud
- OpenStack
- Internal enterprise cloud

## Hybrid Cloud
A mix of on-premises/private cloud and public cloud.

Example:
- Company datacenter connected to AWS through VPN or Direct Connect

## My explanation in plain English
Cloud is not magic. It is someone else's infrastructure, exposed through web consoles, APIs, CLI tools, and automation.
